# 安装与维护说明（草案）

**较早候选已通过一次原生安装检查，但当前候选的完整生命周期及端到端验收尚未完成，没有受支持的 RC 或正式安装包。本说明仅描述候选接口，不代表可以把仓库快照安装到生产环境。**

[English](INSTALL.md) · [实际发布状态](STATUS.md) · [兼容范围](COMPATIBILITY.md)

## 安装前

先使用可丢弃的、完整官方 DX X5 环境。插件不携带 DX 核心，也不能用只导入部分论坛表的测试数据代替官方安装。插件不要求独立的 UCenter 服务，但 DX 自身独立模式所需的账户内核结构仍须完整，不要按表名前缀自行删除。

候选要求 PHP 8.2 以上、Sodium、mbstring、JSON、mysqli、HTTPS 通信；后台监督还需要进程创建和终止能力。数据库使用 InnoDB。仅给予 Web 服务用户正常运行缓存目录所需的写权限，不把程序或语言目录改成 Web 可写，不以 root 运行维护入口，不靠放宽权限消除错误。

现有系统进行获准的安装或升级前先备份。首个通用发行分支面向新安装，不会静默接管已有定制集成的数据；安装包不含数据库、密钥、真实绑定或生产配置。

## 通过验收后的安装顺序

1. 获取明确发布的版本，核对 ZIP 外部 SHA-256 和内部文件清单。一个提交或自己打出的包不等于受支持的发行版。
2. 核对该版本真正测试过的 DX/PHP/数据库组合；不推断兼容 X3.x、子目录或任意端口部署。
3. 将 `upload/` 内容上传到 DX 根目录。工作候选包含插件子树、六个指定的 `source/class/task/task_togya_*.php` 任务入口及 `static/image/task/togya.png`，不整体覆盖官方核心和配置。存在同名自定义任务文件时先核对，不盲目覆盖。
4. 通过 DX 原生 AdminCP 安装 `pintogya`，核对显示名为 **Togya Plugin**、版本一致；完成配置前保持关闭。
5. 核对 DX 原生基本设置里的站点 URL（`siteurl`）。候选将它当作可信的论坛来源：HTTPS、小写主机名、根路径，不含自定义端口、用户信息、参数或片段。它不按任意访问请求的 Host 自动推导；另一个公司官网或首页链接不能代替论坛来源。
6. 核对扫码确认页显示的来源名称。名称变化不改变账号身份，也不迁移绑定。
7. 配置密钥和后台同步。各功能遵循原生权限及已有后台设置，工作源码不再另加发行专用的任务/互动/奖励关闭开关。未验证工作候选不能用于生产，也不能为测试调度而开启真实积分发放。

### 原生六任务

六个类型为 `togya_bind_daily`、`togya_youtube_connected`、`togya_youtube_import_public`、`togya_youtube_import_three_participants`、`togya_answer_other_question`、`togya_created_activity_three_completions`。通过官方 AdminCP 任务中心配置原有用户组、周期与奖励规则；上传文件不会自动创建带金额的任务或发放积分。保留原任务条件，包括原本存在的管理员限制，不能为了测试通过而删除限制。原教程配图及展示路径一并保留。
8. 使用官方 AdminCP 全缓存更新，并在隔离环境验证 PC/Touch、会员/游客和无权限路径，再考虑生产部署。

## 密钥

使用部署侧秘密管理方式生成随机 32 字节密钥，把其无填充 base64url 表示通过 `PINTOGYA_TOKEN_ENCRYPTION_KEY` 一致提供给 Web PHP 与 CLI。不要使用合成测试密钥，也不要把密钥填入插件设置、源码、Git、截图、问题报告或命令输出。

CLI 可通过 `PINTOGYA_TOKEN_ENCRYPTION_KEY_FILE` 指向私有文件；实现会检查文件所有者、模式和链接状态。按部署政策配置，不删除检查来“修复”。安装器不会修改已有文件权限。密钥须与灾备资料安全保管；未经迁移直接更换会使原有加密凭据无法读取。

## 后台同步

候选按真实安装路径在 `/var/cache/` 下派生 Web 根目录之外的私有展示缓存目录。须由部署政策预先配置，Web PHP 与 CLI 使用**同一有效用户**，目录仅所有者可访问；插件不会自动放宽已有目录权限。PHP 文件访问限制也须允许该位置。不能提供合适私有存储的共享主机目前不在已声明支持范围内；不要把私有快照移进公开目录，也不要删除所有者检查来绕行。

插件使用独立且仅限 CLI 的维护入口。以实际 Web 服务用户运行，选择已验证的 PHP 二进制，主机名与 DX 配置保持一致：

```sh
php source/plugin/pintogya/maintenance.php status --host=forum.example.org
php source/plugin/pintogya/maintenance.php run --host=forum.example.org --limit=5
```

这些是接口示例，不代表真实调度已验收。`--host` 不覆盖配置中的可信来源。系统调度器可调用 `run`，前台访问不负责重型同步。候选限制子进程运行时间，仅返回计数和封闭错误码，不返回上游正文。日志只留必要脱敏状态，不用紧密循环重试未知结果，也不靠打开结算测试调度。

## 升级、禁用与卸载

- 升级前确认发行分支、迁移说明及备份，不将通用候选直接覆盖已有定制集成。
- 使用原生禁用操作，并停止该安装的后台调度；禁用不等于删除历史数据。
- 卸载前先解除有效连接，处理或等待扫码请求过期。候选有卸载前检查，因为 DX 会先移除注册信息，再执行卸载脚本。
- 默认保留插件表及安装标识。卸载不是数据擦除或远端撤销工具；这些行为仍须原生门禁验证，不能仅凭说明声称已通过。
- 不通过删改安装 UUID、绑定或奖励表来处理域名/数据库异常。UUID 参与稳定权益命名空间，重建可能改变去重身份。复制数据库或改表前缀须有明确迁移方案，不自动接管。

## 故障处理

| 状态 | 应核对 | 禁止的绕行 |
| --- | --- | --- |
| 插件或功能关闭 | 原生可用状态和基础开关 | 一次打开所有可选操作 |
| 站点来源错误 | `siteurl`、HTTPS、根路径和主机名 | 直接信任请求 Host |
| 安装标识或数据库范围错误 | 安装脚本、配置数据库和前缀 | 清空身份或奖励表强行接管 |
| 密钥错误 | Web/CLI 来源一致，私有文件符合策略 | 回显密钥或移除检查 |
| 私有缓存目录错误 | 根目录外的配置、有效用户及 PHP 文件访问政策 | 改成公开目录、放宽权限或改为开帖回源 |
| `extension_not_verified` | 发布记录中的可选功能状态 | 删除后端门禁让按钮工作 |
| `outcome_unknown` | 脱敏状态和权威记录 | 盲目重放写入 |

重复验收失败遵守[发布状态](STATUS.md)的次数上限并保留证据。组件测试、打包通过或缓存诊断正常，不会自动重置已用尽的安装门禁。
