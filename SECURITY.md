# Security Reporting

Do not disclose real credentials, user records or exploitable production details in public issues. Use GitHub private vulnerability reporting if enabled. If unavailable, open a content-free issue requesting a private reporting channel, without vulnerability details.

Identify the release, affected operation, expected authorization and a synthetic reproduction. Do not send database dumps, cookies or live QR authorization payloads.

There is no supported installable release in this documentation preview. Unreleased snapshots are not supported production deployment targets.
